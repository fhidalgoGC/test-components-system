PROMPT – Crear componente Modal agnóstico con overlay, layout flexible, estados y control externo
Quiero que generes un componente Modal reutilizable y completamente agnóstico, desacoplado de la lógica de negocio, control y data.
El componente NO interpreta ni transforma data.
 Su responsabilidad es únicamente renderizar estructura, layout, overlay y estados visuales, y exponer hooks/callbacks para control externo.

1. Overlay (oscurecer pantalla)
La Modal debe poder oscurecer u ocultar el contenido detrás mediante un overlay configurable.
Prop de overlay
overlay: {
  enabled: boolean,
  opacity?: number,        // 0 – 1
  color?: string,          // ej: rgba(0,0,0,0.5)
  blur?: boolean           // opcional
}

Reglas:
Si enabled es true, el overlay cubre toda la pantalla


El overlay se renderiza debajo del modal y encima del contenido


El Modal NO asume valores por defecto agresivos


Debe permitir una modal sin overlay (pantalla clara)



2. Botón de cerrar (Close button)
El Modal debe permitir mostrar u ocultar un botón de cierre visual en la parte superior.
Prop de botón cerrar
closeButton: {
  visible: boolean,
  position: 'top-left' | 'top-right',
  render?: ReactNode
}

Reglas:
Si render no se provee, se usa un botón visual por defecto


El botón NO cierra la modal por sí mismo


Al hacer click, solo dispara onClose


El cierre real lo decide el controlador externo



3. Layout general del Modal
layout: {
  widthMode: 'full' | 'auto' | 'fixed',
  width?: number,
  minWidth?: number,

  heightMode: 'full' | 'auto' | 'fixed',
  height?: number,
  minHeight?: number
}

Reglas:
El contenido interno no puede forzar el tamaño


minWidth y minHeight son límites absolutos


El Modal nunca se adapta a su contenido automáticamente



4. Estructura del componente
La Modal debe tener tres secciones obligatorias:
Header


Body


Footer


Cada sección renderiza componentes externos sin conocer su contenido.

5. Header / Body / Footer
section: {
  renderType: 'component',
  render: ReactNode,

  heightMode: 'full' | 'auto' | 'fixed',
  height?: number,
  minHeight?: number,

  verticalAlign: 'top' | 'middle' | 'bottom',
  horizontalAlign: 'left' | 'center' | 'right'
}

Reglas:
La Modal solo posiciona


No ejecuta lógica del componente renderizado


Alineaciones deben resolverse por layout



6. Estados del Modal
El Modal debe soportar estados visuales controlados externamente:
statesComponents: {
  idle: StateConfig,
  loading: StateConfig,
  success: StateConfig,
  empty: StateConfig,
  error: StateConfig
}

StateConfig:
StateConfig: {
  renderType: 'component' | 'self',
  render?: ReactNode,

  widthMode: 'full' | 'auto' | 'fixed',
  width?: number,
  minWidth?: number,

  heightMode: 'full' | 'auto' | 'fixed',
  height?: number,
  minHeight?: number,

  verticalAlign: 'top' | 'middle' | 'bottom',
  horizontalAlign: 'left' | 'center' | 'right'
}

Reglas:
El estado reemplaza solo el Body


self usa un fallback interno


component renderiza uno externo



7. Ciclo de estados
Estado inicial: idle


Data asíncrona:


idle → loading → success


Data estática:


Permitir iniciar directamente en success


El Modal no decide el estado



8. Data agnóstica
data?: Array<{
  id: string
  [key: string]: unknown
}>

Reglas:
El Modal no interpreta data


Solo la expone al componente renderizado



9. Callbacks
callbacks: {
  onClose?: () => void,
  onConfirm?: <T>(data: T) => void
}

Reglas:
onClose puede venir de:


Botón cerrar


Overlay (si se habilita)


El Modal no ejecuta cierre directo



10. Hook obligatorio de control
Se debe crear un hook para controlar la Modal externamente.
API
useModalController<T>()

Expone:
{
  isOpen: boolean,
  state: 'idle' | 'loading' | 'success' | 'empty' | 'error',

  open: () => void,
  close: () => void,
  closeWithData: (data: T) => void,

  setState: (state) => void,
  setSelectedData: (data: T) => void,

  selectedData?: T
}

Reglas:
El hook es la fuente de verdad


El Modal es puramente declarativo


El Body puede setear data sin acoplamiento



11. Principios obligatorios
Componente agnóstico


Sin lógica de negocio


Sin manejo interno de estado


Control 100% externo


UI y comportamiento desacoplados

PROMPT – Crear componente List agnóstico con control externo y ciclo de render
Quiero que generes un componente List reutilizable, completamente agnóstico a la data y desacoplado de la lógica de control, carga y paginación.
El componente no interpreta, transforma ni obtiene data.
 Su única responsabilidad es renderizar una colección de ítems y reflejar visualmente el estado de renderizado que recibe desde un sistema de control externo.
El componente posee internamente un controller, pero este NO forma parte de la API pública y NO se pasa como prop al usar <List />.

1. Concepto del componente
La List es una estructura de renderizado secuencial, no un componente de negocio.
No conoce el significado de los datos


No asume estructura interna de los ítems


No ejecuta procesos síncronos ni asíncronos


No decide cuándo cargar, recargar o paginar


No maneja lógica de negocio


Toda la lógica de control:
existe


es explícita


es reutilizable
 pero vive fuera del componente visual y es orquestada mediante un hook externo, al cual la List se conecta internamente.



2. Requisitos funcionales obligatorios
La List debe:
Renderizar ítems únicamente a partir de la data recibida


Delegar el render de cada ítem a un componente externo


Soportar:


sin scroll


scroll normal


scroll infinito con umbral anticipado


Emitir eventos de scroll y scroll infinito


Soportar paginación por cantidad de ítems


Permitir control total mediante un hook externo


Permitir recargar el contenido completo


Soportar data síncrona y asíncrona (controlada externamente)


Reflejar estados de renderizado de forma declarativa



3. Estados de renderizado (OBLIGATORIOS)
El sistema de control debe manejar explícitamente los siguientes estados:
renderIdle
 Estado inicial, sin data ni loading


renderLoading
 Estado visual de carga, puede coexistir con data previa


renderComplete
 Data cargada y renderizada correctamente


renderError
 Error durante la carga; la List no resuelve el error


La List nunca decide transiciones, solo las refleja visualmente.

4. API del componente List (contrato de props)
⚠️ El controller NO se pasa como prop.
 La List se vincula internamente al controller expuesto por el hook.
type ListProps<T> = {
  id: string;

  layout?: {
    widthMode?: "full" | "auto" | "fixed";
    width?: number;
    minWidth?: number;

    heightMode?: "full" | "auto" | "fixed";
    height?: number | "auto";
    minHeight?: number;
  };

  callbacks?: {
    onScroll?: (id: string) => void;
    onScrollInfinity?: (page: number) => void;
  };

  behaviors?: {
    scroll?: "normal" | "infinityScroll" | "none";

    paginator?: {
      maxItem: number;
    };
  };

  loading?: {
    renderType?: "component" | "self";
    render?: ReactNode | Component;
    position?: "top" | "bottom" | "over";
  };

  item: {
    renderType: "component";
    render: (item: T, index: number) => ReactNode;

    heightMode?: "full" | "auto" | "fixed";
    height?: number | "auto";
    minHeight?: number;
  };

  data: T[];
};


5. Hook de control externo (OBLIGATORIO)
Debe existir un hook totalmente desacoplado del UI, responsable de manejar el ciclo de vida del render:
const controller = useListController<T>();

Este hook:
expone estado y acciones


controla la data


controla la paginación


controla el render state


La List consume este controller de forma interna, sin exponerlo al consumidor.

6. API del hook de control
type RenderState =
  | "renderIdle"
  | "renderLoading"
  | "renderComplete"
  | "renderError";

type ListController<T> = {
  // Data
  setData: (data: T[]) => void;
  appendData: (data: T[]) => void;

  // Pagination
  setPage: (page: number) => void;
  setPageSize: (size: number) => void;

  // Render lifecycle
  setRenderState: (state: RenderState) => void;
  getRenderState: () => RenderState;

  reload: () => void;

  // Info helpers
  getPage: () => number;
  getPageSize: () => number;
  getTotalItems: () => number;
};


7. Reglas de manejo de data
setData
Reemplaza completamente la data


Reinicia la paginación


appendData
Agrega data respetando el pageSize


En scroll infinito, incrementa la página


La List:
Nunca muta la data


Nunca ordena ni filtra


Nunca carga data por sí misma



8. Scroll infinito
El evento de scroll infinito:


Se dispara al alcanzar un umbral previo al final


No al llegar exactamente al último ítem


La List:


No hace fetch


No maneja promesas


El consumidor:


Usa el hook para agregar data


Controla loading y estado de render



9. Flujo correcto de carga (sync y async)
Síncrono
controller.setRenderState("renderLoading");
controller.setData(data);
controller.setRenderState("renderComplete");

Asíncrono
controller.setRenderState("renderLoading");

fetchData()
  .then(data => {
    controller.setData(data);
    controller.setRenderState("renderComplete");
  })
  .catch(() => {
    controller.setRenderState("renderError");
  });


10. Ejemplo conceptual de uso – Scroll infinito
const controller = useListController<Item>();

useEffect(() => {
  controller.setRenderState("renderLoading");

  fetchInitial()
    .then(data => {
      controller.setData(data);
      controller.setRenderState("renderComplete");
    });
}, []);
